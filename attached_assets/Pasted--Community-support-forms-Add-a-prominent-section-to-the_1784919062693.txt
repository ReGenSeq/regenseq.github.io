## Flowcell request form

Create a page titled:

```text
Request or Purchase Flowcells
```

Suggested introductory text:

> Request flowcells for your project or purchase additional flowcells for $50 each. Submit the form below and the team will follow up with availability and next steps.

Clearly display:

```text
Price: $50 per flowcell
```

Do not calculate tax, shipping, or a final payable amount unless the existing project already has a checkout or payment workflow. This is a request form, not an online payment form.

### Required fields

Include:

* Full name
* Email address
* Organization or institution
* Number of flowcells requested
* Intended use or project description

### Optional fields

Include:

* Laboratory or research group
* Requested date
* Shipping or pickup preference
* Additional notes

### Quantity behavior

The quantity field must:

* Accept positive whole numbers only
* Default to `1`
* Have a minimum value of `1`
* Display the estimated total dynamically

Example:

```text
3 flowcells × $50 = $150 estimated total
```

Label this clearly as an estimate.

### Form submission

On submission:

* Validate all required fields
* Validate the email format
* Prevent zero, negative, decimal, or invalid quantities
* Show a clear success message
* Preserve entered values when validation fails
* Prevent accidental duplicate submissions
* Send or store the submission using the project’s existing form-handling system

If the application already uses an email service, database, CRM, server action, API route, or third-party form handler, reuse it.

If no form infrastructure exists, implement the simplest maintainable server-side submission flow supported by the current stack.

Do not expose private email addresses or API credentials in client-side code.

The form notification should be sent to the existing project contact responsible for flowcell requests. If that contact cannot be identified in the codebase, use a clearly marked environment variable or configuration placeholder rather than inventing an address.

Suggested environment variable:

```text
FLOWCELL_REQUEST_RECIPIENT
```

### Submission email or record

Include:

* Submission type: Flowcell request
* Requester’s name
* Requester’s email
* Organization
* Quantity
* Estimated total
* Intended use
* Requested date
* Delivery preference
* Notes
* Submission timestamp

Use a subject such as:

```text
New flowcell request — [Name] — [Quantity] flowcells
```

```text
Help Find a Sequencer
```

Suggested introductory text:

> Tell us who you are, where you are located, and what you want to accomplish. We will use this information to help identify a suitable sequencer or sequencing resource.

The form should be routed to **Kunal**.

Do not invent Kunal’s email address. First inspect the existing project configuration, contact data, team page, environment variables, or form handlers for an existing email address.

If no verified address exists, use a server-side environment variable:

```text
SEQUENCER_REQUEST_RECIPIENT
```

Add a code comment or setup note explaining that this value should contain Kunal’s verified email address.

### Required fields

Include:

* Full name
* Email address
* Organization or institution
* Where are you located?
* What do you want to do?

### Sequencing details

Also include:

* Project or experiment description
* Sequencing platform needed, if known
* Current sample type
* Approximate number of samples
* Desired timeline
* Whether the requester already has access to sequencing equipment

For the sequencing platform field, offer options such as:

* Illumina
* Oxford Nanopore
* PacBio
* Other
* Not sure

For equipment access, use:

* Yes
* No
* Limited access
* Not sure

### Helpful optional fields

* City
* State, province, or region
* Country
* Preferred travel distance
* Collaboration interest
* Funding status
* Additional constraints or notes
